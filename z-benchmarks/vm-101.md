# VM 101: Ubuntu image, CLI start, GUI control

Three open-source ways to boot an Ubuntu image from the terminal and then manage it with a UI.

## 1. GNOME Boxes

Best for a quick desktop-first VM.

### Command

```bash
gnome-boxes
```

### How to use

1. Open GNOME Boxes.
2. Click `+`.
3. Choose `Create a virtual machine`.
4. Select your Ubuntu ISO or disk image.
5. Finish the wizard and start the VM.

### Pros

- Very simple setup.
- Good for casual local VMs.
- Open source.

### Cons

- No strong CLI workflow for creating/starting a VM from an image.
- Less flexible than libvirt-based tools.
- Not ideal if you want repeatable scripted launches.

## 2. QEMU + libvirt + virt-manager

Best balance of performance, flexibility, and GUI control.

### Command

Install the tools:

```bash
sudo apt install qemu-kvm libvirt-daemon-system libvirt-clients virt-manager
```

Start the GUI:

```bash
virt-manager
```

### How to use

1. Install the packages above.
2. Open `virt-manager`.
3. Create a new VM or connect to an existing libvirt VM.
4. Use QEMU/libvirt under the hood for the actual VM runtime.

### Pros

- Powerful and flexible.
- Good GUI for inspection and control.
- Open source and widely used.
- Better fit if you want to tune CPU, RAM, disk, and networking.

### Cons

- More setup than GNOME Boxes.
- More moving parts.
- The UI is less beginner-friendly than Boxes.

## 3. virt-install + virsh

Best for terminal-first VM creation with later GUI control.

### Command

Install the tools:

```bash
sudo apt install qemu-kvm libvirt-daemon-system libvirt-clients virtinst virt-manager
```

Create and start a VM from an ISO:

```bash
sudo virt-install \
  --name ubuntu-vm \
  --memory 4096 \
  --vcpus 2 \
  --disk size=30 \
  --cdrom /path/to/ubuntu.iso \
  --os-variant ubuntu24.04 \
  --network network=default \
  --graphics spice

sudo virt-install \
  --name ubuntu-vm \
  --memory 3096 \
  --vcpus 2 \
  --disk size=30 \
  --cdrom ./ubuntu-26.04-desktop-amd64.iso \
  --os-variant ubuntu26.04 \
  --network network=default \
  --graphics spice
```

List and manage VMs:

```bash
virsh list --all
virsh start ubuntu-vm
virsh shutdown ubuntu-vm
```

### How to use

1. Create the VM with `virt-install`.
2. Manage power state and lifecycle with `virsh`.
3. Open `virt-manager` later if you want a GUI for the same VM.

### Pros

- Best CLI control.
- Easy to script and automate.
- Uses the same open-source libvirt stack as the GUI tools.
- Good for repeatable lab setups.

### Cons

- More command-line knowledge required.
- You need to manage image paths and VM options yourself.
- Less beginner-friendly than Boxes.

---

## Recommendation

- Choose **GNOME Boxes** if you want the simplest UI.
- Choose **virt-manager** if you want the best balance of power and usability.
- Choose **virt-install + virsh** if you want CLI-first control and a GUI only when needed.

## Working CLI Flow For An ISO On Desktop

If the ISO sits in your home Desktop folder, the hypervisor may not be able to read it directly. 

A reliable approach is to copy it into libvirt's image directory first.

### Commands

```bash
sudo mkdir -p /var/lib/libvirt/images
sudo cp /home/jalcocert/Desktop/ubuntu-26.04-desktop-amd64.iso /var/lib/libvirt/images/
```

Then install from the copied ISO:

```bash
sudo virt-install \
  --name ubuntu-vm \
  --memory 3096 \
  --vcpus 2 \
  --disk size=30 \
  --cdrom /var/lib/libvirt/images/ubuntu-26.04-desktop-amd64.iso \
  --os-variant generic \
  --network network=default \
  --graphics spice
```

### Alternative Fix

If you prefer to keep the ISO in `~/Desktop`, the hypervisor user needs search access to the parent directories and read access to the ISO:

```bash
chmod 755 /home/jalcocert
chmod 755 /home/jalcocert/Desktop
chmod 644 /home/jalcocert/Desktop/ubuntu-26.04-desktop-amd64.iso
```

This is simpler, but copying the ISO into `/var/lib/libvirt/images/` is usually cleaner for a one-off VM install.
